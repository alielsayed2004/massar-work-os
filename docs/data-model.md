# نموذج البيانات (Data Model) & الصلاحيات

## 1. الكيانات الرئيسية (Entities)

- **profiles:** بيانات المستخدمين الأساسية (الاسم، الدور، حالة الحساب، والـ `team_id` في حال كان داخلياً). ترتبط مباشرة بهوية `auth.users` في Supabase.
- **departments & teams:** هيكلة فريق مسار الداخلي.
- **clients & client_memberships:** العملاء الخارجيين والربط بين المستخدم العميل والجهة.
- **projects:** المشروعات التابعة للعملاء والمدارة داخلياً.
- **tasks:** المهام الداخلية المسندة للموظفين. 
- **handover_requests:** طلبات نقل المهام، مع قيود تمنع تعدد الطلبات المفتوحة لنفس المهمة.
- **activity_events:** سجل التدقيق والأنشطة (Logs) محمي ضد المسح العرضي.

### دورة التسليمات (Deliverables)
- **deliverables:** الحاوية العامة للتسليم المرتبطة بالمشروع.
- **deliverable_versions:** النسخ المرقمة من التسليم؛ كل نسخة لها دورتها المنفصلة وحالتها الخاصة (draft, internal_review, approved_internally, shared_with_client...).
- **review_decisions:** سجل قرارات المراجعة (اعتماد أو طلب تعديل) لكل مرحلة (داخلي/عميل).
- **files & comments:** تابعة للمهام أو لنسخ التسليم (XOR Constraint).


## 2. مصفوفة الصلاحيات (Role Permissions Matrix)

| الكيان / الواجهة | Admin | Manager (مدير الفريق) | Member (الموظف) | Client (العميل) |
|------------------|-------|------------------------|-----------------|-----------------|
| **المستخدمين/الفرق** | قراءة / كتابة | قراءة (فريقه) | لا يوجد | لا يوجد |
| **العملاء والمشروعات**| قراءة / كتابة | قراءة | قراءة (للمشروعات المسندة إليه مهام فيها) | قراءة (لمشروعاته فقط) |
| **المهام** | قراءة / كتابة لجميع المهام | قراءة / كتابة (لمهام فريقه فقط) | قراءة / تحديث الحالة (لمهامه فقط) | لا يوجد (مخفية تماماً) |
| **نقل المسؤولية** | اتخاذ القرار كبديل (Fallback) | اتخاذ القرار لمهام فريقه | إنشاء طلب نقل لمهامه فقط | لا يوجد |
| **التسليمات** | إدارة كاملة، مشاركة مع العميل | إدارة كاملة، مشاركة مع العميل | رفع وتحديث نسخ التسليم الخاصة بمشروعه | **لا يرى إلا النسخ (المشاركة)، يتخذ قرارات الاعتماد أو التعديل** |
| **الملفات/التعليقات**| وصول كامل | وصول كامل | وصول للنطاق المسموح (مهامه وتسليماته) | **مسموح بتنزيل ملفات النسخ المشاركة، وقراءة/كتابة التعليقات الموجهة للعميل (Client Scope)** |

## 3. قيود قاعدة البيانات (Database Constraints)
- يتم استخدام `status` كبديل عن `Cascading Deletes` لبعض الكيانات الهامة كالمستخدمين لمنع فقدان السجلات المرتبطة.
- `ON DELETE SET NULL` للحفاظ على التاريخ في سجل الأنشطة عند حذف عناصر معينة.
- فهارس فريدة: `UNIQUE(deliverable_id, version_number)` لضمان ترتيب النسخ.
